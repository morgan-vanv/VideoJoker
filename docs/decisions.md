- **2026-11-07** OSRS linking v1 (`docs/osrs-design.md`): alts first-class, no ownership checks (we trust the server), `/osrs` command group; Wise Old Man's own bot stays for stats/leaderboards. Flexing is "paste-it": the bot owns the Discord webhook (Manage Webhooks), hands it out privately and can rotate it; shared Dink settings live publicly in `osrs/dink-settings.json` (from swannobi's config) with a test that forbids webhook keys, because the old shared webhook leaked from a public config file. - **2026-11-07** OSRS deaths are a per-player opt-in in /osrs register (order: flexing → deaths → clan), posted in their own channel by a "sit, respectfully" webhook; `deathEnabled` left out of the shared Dink settings so the periodic re-import can't switch deaths back on for people who said no.
- **2026-11-07** Music playback: yt-dlp downloads the chosen format and pipes it into ffmpeg (music/stream.py) instead of ffmpeg fetching the link. YouTube signs stream links for the IP + headers that requested them, so ffmpeg's own fetch got 403 in production; this also handles SoundCloud HLS natively. yt-dlp runs in /tmp (its HLS downloader writes chunk files to the current folder, and /app is read-only).
- **2026-11-07** Pin `davey==0.1.7` (Dependabot ignores >=0.2, `tests/test_voice_deps.py` guards it): davey 0.2.0 (2026-11-02) + discord.py 2.7.1 never installs the DAVE encryption key, so the bot plays unencrypted audio into an E2EE call and nobody hears it. Production logged `DAVE protocol 1, encrypting False` with loud frames. Unpin when a discord.py release supports davey 0.2 (Rapptz/discord.py#10549).
- **2026-11-07** Music loudness: every song goes through ffmpeg's `loudnorm` (EBU R128) at -20 LUFS, so YouTube and SoundCloud match and sit below streaming-app loudness (~-14); /volume 100% now means that level. The YouTube stutter was buffering: Python 3.14's 128 KB pipe buffers plus discord.py's never-flushing stdin writer fed ffmpeg ~6 s lumps, and the small pipe held yt-dlp to playback speed so YouTube dropped its idle connection. Fixed with a flushing writer, an in-memory read-ahead (up to 32 MB) and a short prebuffer.
- **2026-11-07** Music loudness target lowered to -26 LUFS (from -20): Morgan found -20 still too loud for people joining a call for the first time. /volume up to 200% gives back the loud end.
- **2026-11-07** Spotify + Tidal links (music/catalogs.py), read for track names only and played from YouTube. Spotify's Developer Policy forbids integrating its platform with another service's streams and playing to several listeners, so production runs **embed-page only** (no Spotify developer app, no keys; Morgan's call). The official-API path stays in the code for a possible throwaway Premium account later. TIDAL's guidelines want written approval to integrate with another service; Morgan accepts that risk with a fresh TIDAL account that owns the app (worst case: the app is revoked).
- **2026-11-07** XP rank ladder replaces Pancake (`ranks/`, `cogs/ranks.py`): LOWLY SERFS at 1 XP, SWORN SWORDS at 250, LORDS at 1,000 by default, set per server with `/ladder setup` and stored in a new `rank_tiers` table (off until set up). Ranks only go up and are mutually exclusive: a promotion adds the new rank and removes only the lower ones, and anyone already at or above what they've earned is never touched, so Pancake's ranks survive. Server XP stays global (one server in prod).
- **2026-11-07** The bot now uses the privileged `members` intent (Morgan's call: it's only his server) so `/ladder tidy` can see everyone and clean up Pancake's stacked roles; the host layer needed it next anyway. The reaction-roles stub is gone (Discord onboarding does that job); its table stays for rollbacks.
- **2026-11-07** Rank-up announcements left out of the first version on purpose: Morgan wants something unobtrusive and will decide how. XP reaches the ladder through a custom `server_xp_gained` event, so it always sees the new total.
- **2026-11-07** One XP number: 1 per message, 5 per slash command, lifetime (never resets). Messages also earn 1 USh, commands earn none. The `xp` table keeps its raw counts (`server_xp` = messages, `bot_xp` = commands) and the total is worked out from them (`TOTAL_XP_SQL` in `core/database.py`), plus a new `bonus_xp` column: no column changes meaning, so a rollback still works. Changing the weights later re-scores everyone's history, which is fine for us.
- **2026-11-07** `/ladder tidy` also tops up anyone wearing a rank with less XP than it needs (Pancake's ranks came from Pancake's XP) to that rank's minimum, as `bonus_xp`. It never lowers XP.
- **2026-11-08** Personal voice channels replace the TempVoice bot (`personal_vc/`, `cogs/personal_vc.py`), deliberately toned down: join-to-create (join the lobby, get your own channel, deleted when the last person leaves) because it needs no commands to use, and three modes (🔓 Open, 🔒 Locked, 👻 Hidden) instead of separate lock/hide toggles, so there's no confusing fourth "hidden but open" state. Five buttons in each channel's own chat, usable by its owner only (Morgan dropped the separate controls channel: the buttons are already where people are); each owner's mode and guest list are remembered. New tables only (`personal_vc_*`); the bot gets Manage Channels + Move Members on that category only.
- **2026-11-08** New `ush_ledger` table: one row per real USh movement (`/pay` now; gambling or a shop later, with NULL as "the bank"), written in the same transaction as the transfer so history and balances can't disagree. Passive message income is not logged (one row per message would bury the payments). New table only, so a rollback still runs.
- **2026-11-08** Slash commands earn XP at most once per 60 s per person (any command counts; `COMMAND_XP_COOLDOWN_SECONDS`), kept in memory so a restart resets it. Messages are untouched: Morgan prefers rewarding engagement over anti-farming for now, this only stops `/ping` spam being the fastest way up the ladder.
- **2026-11-08** `/leaderboard` built (Morgan's call, it was a crew stub): top 10 non-bot members with more than 0, ties share a place (1, 2, 2, 4), XP and USh behind two buttons, plus the viewer's own row if they're further down. The buttons switch the shared message only for whoever ran it; anyone else's click opens that board privately with their own row (an invitation to check where you stand, instead of a "not yours" refusal). The old `category` choice is gone.
- **2026-11-08** `/rank`, `/balance` and `/leaderboard` are public (friends can show off) but never ping: lookups send with no allowed mentions, and names sit inside embeds. `/pay` pings the recipient only, so a note can't ping anyone else. The "how you earn" line is built once (`standing/lines.py`) from the numbers in `core/database.py` and shared by every footer.
- **2026-11-08** `/help` (`cogs/guide.py`, words in `guide/lines.py`) is the first stop the server's onboarding points newcomers to: one ephemeral card touring the core features, ending with Morgan's "For the rest of the commands: /listcommands". A section only shows when its feature is on (`guide/tour.py`, plain inputs, tested): no ladder drops the ranks section (the leaderboard section then says how XP is earned), no personal-VC lobby (or a deleted one) drops that one, an unloaded cog drops its own, and DMs skip the server-specific ones. A test fails if the card mentions a command that doesn't exist.
- **2026-11-08** `/listcommands` lists subcommands under their full names (`/ladder show`) and leaves out VIP-only commands; `/listadmincommands` (VIP-only, ephemeral) lists exactly those, from the same code with the opposite filter. "VIP-only" means the command has `@is_vip()`: the check carries a `vip_only = True` tag that `is_vip_command()` looks for, so a new VIP command needs nothing extra. VIP is the only gate the bot has (the owner can't be banned, but nothing is owner-only). Discord's `/` menu still shows `/listadmincommands` to everyone (Discord has no "VIP" permission); non-VIPs get the usual "not VIP" reply.
- **2026-11-08** Rank-up notes: climbing the ladder leaves a private (ephemeral) note on your next slash command in that server, or on the very command that earned the rank, and never in a channel or a DM, so it stays out of the way: members who never use commands are simply left alone (their new role still shows). Climb twice before a command and only the latest rank's note shows. What the rank unlocks is read from the roles' real permissions (new role minus @everyone minus the lower ranks), so it stays right when Morgan edits a role. Notes live in a new `rank_up_notes` table so deploys' restarts don't lose them; a note that fails to send is put back. Commands reach the ladder through one custom event, `slash_command_finished`, which promotes first and then delivers, so a rank earned by that command is always saved before its note is looked for.
- **2026-11-09** `/ping` is hidden from non-admins with Discord's `default_permissions(administrator=True)` rather than gated with `is_vip()`: the point is a shorter `/` menu (so `/play` comes up sooner), and only Discord-side default permissions remove a command from the menu. The server owner can re-grant it per role in Integrations.
- **2026-11-09** Replaced the above: `/ping` became the text command `@VideoJoker ping` (admins, servers only), because Discord always lists a slash command for anyone who can run it, admins included, and Morgan wants it out of the autofill entirely. Text commands work without the message content intent because they start with a mention. Unknown `@VideoJoker ...` words and non-admins get silence, not an error log.
- **2026-11-10** Event alerts (`cogs/event_alerts.py`, `event_alerts/`) lean on Discord's own scheduled events: Discord does the scheduling, weekly repeats, cancelling or moving one week, the RSVP ("Interested") and the "it's starting" notification. The bot only adds what Discord doesn't: a heads-up before each event (24h and 1h by default; `EVENT_ALERT_TIMES` in `.env`) pinging everyone marked Interested, and a notice when an event's time or location changes or it's cancelled, triggered by the edit itself (no command). Morgan chose this over a bot-run scheduler (`/session schedule|cancel|move`, its own RSVPs and weekly logic): far less to build and to break on game night, and no new permissions, because the bot never makes or edits events. One VIP command, `/seteventalerts [channel]` (empty = off), kept out of non-admins' `/` menu. Made for the Vampire campaign server and Ugandan Commandos alike; no link to Foundry (the game's secrets stay there). New tables only (`event_alert_channels`, `event_reminders_sent`); who's Interested is held in memory only. **Exception to the VJ-voice rule (Morgan, 2026-11-11):** the alert posts are plain on purpose (headline, small grey Interested line, event card), since people skim schedule notices; keep flavour text out of `event_alerts/lines.py`.
